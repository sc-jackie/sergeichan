    2026-07-01 — Self-improving skills: feedback ledger + approve-gated skill-improve loop¶

    Skills are procedural memory; without a feedback loop they're tech debt (Warp/Anthropic; Nous Hermes-agent curator pattern). Added a native loop rather than installing a plugin (UniM0cha/claude-self-improving-skills and friends are Claude-Code-hook-only, write to ~/.claude/skills/, and mostly auto-patch — none fit the vault-as-source-of-truth model or the vault's no-auto-rewrite contract).

    Shape: skill-feedback is an append-only ledger (capture only — no edits). skill-improve reads open rows, drafts one concrete diff per skill, and stops for Sergei's approval before applying — matching skill-builder's conscious-agent contract. Wiring reuses existing loops (no new cron): session-end captures ambient feedback (step 4b); weekly-review step 0 runs the curator pass (propose diffs + prune ledger).

    Borrowed from the proven tools, minus auto-patch: provenance footer + improve_count: telemetry in skill frontmatter (skill-builder), weekly curator/consolidation, and rollback-by-git (one skill per commit → clean git revert; no backup files). Boundary: jos-compound = code fixes (docs/solutions/); skill-improve = skill-behavior (the .md itself).

    2026-07-01 — VPS agent-skills → mechanical harness; ops alerts → one gateway¶

    Two locked calls from closing the journal-linking gap and the ops-routing loose ends:

    Agent-skills don't run on VPS cron — re-architect as a mechanical harness. Every VPS cron job is no_agent: it shells hermes -z <prompt> for one-shot text, and the Python script writes the files. There is no file-editing agent loop. So skills that edit multiple vault files (daily-linking, person-enrich) can't run "folded into morning-brief" as documented. The pattern that works is the one every cron already uses: Python harness does the deterministic file ops; the LLM (if needed) is one hermes -z call returning a judgment. daily-linking v1 needs no LLM at all — Vault/References/ is a bounded, known entity set, so an inbound linker (journal mention of a known person/place → ## See also) is pure whole-word matching. Semantic edges are the only part that needs hermes -z; deferred to v2. (daily-linking-vps.py.)

    Agent-cron entries MUST be shims, not symlinks (AGENT_CRON_ENTRIES in hermes-vps-link-scripts.sh): the Hermes cron rejects any entry that resolves outside ~/.hermes/scripts/. A symlinked .sh fails the path-check; a shim (exec bash <repo-path>) passes. New agent-cron .sh wrappers must be added to that list.

    Ops alerts route through one place — hermes-ops-notify.sh (gateway → @persik_hermes_bot, finbot fallback). Scripts that hand-roll their own POST to Newfin /api/cron/ops-notify land on @Persik_finbot (the finance bot), which owns the only bot token in that repo. Ops/CI/deploy/janitor alerts belong on the Hermes bot. Every notifier shells the one .sh; hermes-intel-weekly is the sole intended direct-to-finbot sender (it's a finance digest). Journal-capture (mechanical) + this linker are complementary, not duplicates.

    2026-06-30 — Repo as source of truth for VPS scripts (OKF Phase 3 reversal)¶

    OKF Phase 3 ("scripts live ONLY in ~/.hermes/scripts/, deleted from the Jackie-OS repo") was reversed after a production outage: brief-to-telegraph.py was dropped from the VPS symlink farm with no repo backup, silently breaking the morning brief. Permanent model going forward: Jackie-OS repo is the single source of truth for all operational scripts, under System/{coo,capture,ops,periodic,work,lib}/; the VPS runs from the checkout via a symlink farm (System/scripts/hermes-vps-link-scripts.sh, idempotent, run after each git pull). Drift and accidental deletion are now structurally impossible — the repo IS the scripts. Agent-cron entries get real shims (Hermes SDK path-check requires non-symlinked entry scripts); everything else (sourced libs, OS-cron scripts) stays as symlinks to avoid the exec-hijack trap. OKF Phases 1 (frontmatter) and 2 (global-skills removal) stand; Phase 3 and the "portable vault-only bundle" goal are dropped. See docs/solutions/workflow-issues/morning-brief-missing-telegraph-module.md.

    2026-06-23 — Fractal review system¶

    • Period-note naming: a bare slug (e.g. [[2026-W25]]) = Sergei's voice only; the brief suffix = AI lens only. All AI briefs live in Briefs/ (Briefings/ deprecated).
    • Period review flow: brief → read → coach session → co-write note, for all three horizons (week/month/year). Daily stays async (no session).
    • Ownership: the Coach role owns period sessions (W/M/Y); COO content lives in the AI brief.
    • Vault/CLAUDE.md exception: agents may create + co-write period notes (YYYY-Www.md, YYYY-Mmm.md, YYYY.md) after in-session approval; never mutate prior journal content.
