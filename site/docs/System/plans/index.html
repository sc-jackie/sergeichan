    Jackie OS Planning Workflow¶

    This folder is the working planning surface for Jackie OS itself (skills, vault, operator, automations).

    Source of truth¶

    Start with roadmap-index.md. It is audited against shipped skills, vault layout, and merged commits. If a checkbox in an older plan disagrees with what shipped, the shipped state wins and the plan should be deleted (after capturing any durable decision) or corrected.

    Two ledgers, both permanent (never deleted): roadmap-index.md § Shipped (deliverables — what + when) and decisions-log.md (the durable why — locked decisions, supersessions, architecture). Plan bodies are not retained after ship; git log --full-history -- System/plans/ recovers any of them.

    Runtime skills in System/skills/ are source of truth for how things run; plans are blueprints until shipped.

    Current flow¶

    1. Check roadmap-index.md for the current active initiative.
    2. Read the active initiative doc in this folder (or pull from future-improvements.md for net-new work).
    3. If the initiative is still roadmap-level, create a dated implementation plan before building: YYYY-MM-DD-<topic>.md via jos-plan / jos-plan.
    4. When the work ships (delete-on-ship, 2026-06-29): record the deliverable in roadmap-index.md § Shipped, add any durable decision to decisions-log.md, then delete the dated plan body. No archive/ of full bodies — git history is the audit trail.
    5. Catalog cleanup (required) — in the same commit, edit future-improvements.md: remove shipped bullets, or mark 🔵 + gap only for partials; bump roadmap-index.md audit stamp. Contract: session-end § Catalog cleanup.
    6. Never delete future-improvements.md, decisions-log.md, or roadmap-index.md — prune/append, don't remove.

    File types¶

    • roadmap-index.md — current status, priority order, and the Shipped deliverable ledger (permanent).
    • decisions-log.md — durable decisions/rationale ledger (permanent).
    • future-improvements.md — owner-prioritized idea catalog (stays active, no date prefix).
    • YYYY-MM-DD-<topic>.md — roadmap, initiative, or implementation plan (deleted on ship, after the two ledgers are updated).

    Layout¶

    • System/plans/ — active plans + the two permanent ledgers (roadmap-index.md, decisions-log.md).
    • History — shipped plan bodies are not kept in-tree; git log --full-history -- System/plans/ recovers them.
