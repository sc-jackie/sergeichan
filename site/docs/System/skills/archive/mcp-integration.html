    MCP integration guide¶

    Purpose: wire a new MCP server into a Claude Code session or Jackie-OS agent. MCP (Model Context Protocol) servers extend the agent with external tools — GitHub, databases, SaaS APIs — without touching the codebase.

    Trigger: "add an MCP server", "wire in \<server>", "mcp integration"

    5-step process¶

    1. Find the server¶

    • Official catalog: github.com/modelcontextprotocol/servers (reference + community list).
    • In-session: if an mcp-registry server is connected, ask the agent to search_mcp_registry for the capability.
    • Vendor docs: most SaaS tools (Linear, Supabase, Sentry…) document their own MCP endpoint — prefer the vendor's instructions when they exist.

    2. Add it (pick the right scope)¶

    claude mcp add is the canonical path (run claude mcp --help for the current flags):

    # stdio server (runs a local command):
claude mcp add <name> -- npx -y @scope/server-package

# remote server (HTTP/SSE):
claude mcp add --transport http <name> https://mcp.example.com/mcp

    Scope flag -s decides where the config lives — this is the decision that matters:

    Scope Config file Who sees it Use for
    local (default) your ~/.claude.json, entry scoped to this project only you, only here experiments
    user (-s user) ~/.claude.json you, in every project personal tools (GitHub PAT, calendar)
    project (-s project) .mcp.json at repo root — checked into git every agent/collaborator in the repo repo-standard tooling

    Manual alternative: edit .mcp.json directly (same mcpServers JSON shape the add command writes; validate with jq . .mcp.json).

    3. Secrets (critical)¶

    Never put a token in .mcp.json (it's committed) or any markdown. Instead:

    1. Put the key in .secrets/<servername>.env (Jackie-OS convention; see existing telegram.env, linear.env) — then immediately chmod 0600 .secrets/<servername>.env.
    2. Reference it by env-var expansion in .mcp.json — supported syntax is ${VAR} / ${VAR:-default}:
    {
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_TOKEN}" }
    }
  }
}
    1. Export the var before launching (source the env file in your shell profile or launcher script) — Claude Code expands it at startup.

    OAuth-based remote servers (Linear, claude.ai connectors) need no key file — authenticate once via /mcp in-session.

    4. Verify¶

    claude mcp list          # all configured servers + connection status
claude mcp get <name>    # one server's details

    In-session: run /mcp — shows each server's status and handles OAuth. Connected tools appear to the agent as mcp__<server>__<tool>. Spot-check one real tool call end-to-end before relying on it.

    5. Codify (so agents know it exists)¶

    Mention it once in the skill or doc that depends on it, e.g.:

    **MCP:** needs the GitHub MCP server (project scope, `.mcp.json`; setup: [[mcp-integration]]).

    If every agent in the repo should have it, use -s project so .mcp.json travels with the clone — that IS the codification.

    Worked example: GitHub MCP¶

    # 1. token → secrets file (repo-scoped convention)
printf 'GITHUB_TOKEN=ghp_yourtoken\n' > .secrets/github.env && chmod 0600 .secrets/github.env

# 2. add at project scope, token via env expansion
claude mcp add -s project github \
  --env GITHUB_PERSONAL_ACCESS_TOKEN='${GITHUB_TOKEN}' \
  -- npx -y @modelcontextprotocol/server-github

# 3. load + verify
export GITHUB_TOKEN=$(grep -m1 GITHUB_TOKEN .secrets/github.env | cut -d= -f2-)
claude mcp list   # github: connected

    Then in a session: /mcp shows github connected, and tools like mcp__github__search_repositories are callable. Codify with one line in the skill that uses it.

    Troubleshooting¶

    • Server missing from claude mcp list: wrong scope (added local in another project?), or JSON syntax — jq . .mcp.json.
    • Fails to start: run the command + args by hand in a terminal; usually a missing binary or bad package name. Prefer npx -y so the package resolves on first use.
    • Secret not expanding: ${VAR} must be set in the environment that LAUNCHES Claude Code — echo $VAR in that shell first.
    • OAuth loop: re-run /mcp and complete the flow; headless/cron sessions can't do interactive OAuth (known limitation — such servers are absent there).
    • Anything else: claude mcp --help is the source of truth; don't trust remembered flags.
