    b-unit-day-log¶

    Purpose: mirror B-Unit visit execution into the matching curriculum day-NN.md ## Done section — dated bullets for what actually happened (walk, calls, Bim briefing, Prove, etc.).

    Trigger: folded into journal-capture after journal append · wrap-up when B-Unit visit is active (Jul 2–22) · on demand "sync b-unit log" · "b-unit day log".

    Role: CMO / COO.

    Output: append-only bullets under Projects/B-Unit/curriculum/week-*/day-NN.md → ## Done (one file = one visit day; calendar date routes the row).

    Two day numbers (don't mix them up)¶

    Label Meaning Example Jul 2
    Visit day Day 1–21 of the Warsaw visit (project clock) Visit day 1
    Curriculum day Day 1–7 inside each week folder (day-01.md … day-07.md) week-01-foundation/day-01.md

    Calendar → file: 2026-07-02 → visit day 1 → week-01-foundation/day-01.md.
    2026-07-09 → visit day 8 → week-02-mind/day-01.md (week 2 curriculum day 1).

    Each day file shows Visit day N · {Weekday} YYYY-MM-DD under the title and in ## Done.

    Telegram → curriculum (automatic)¶

    When you journal to Persik, prefix B-Unit lines so the hourly capture can route them:

    B-Unit: morning walk + stretch done. Breakfast together.

    Aliases (same behavior): bunit: · Bim day:

    Not synced: therapy, Polish class, Newfin — anything without the prefix stays in Vault/YYYY-MM-DD.md only.

    Mechanical runner: System/capture/b_unit_day_log_sync.py (called from journal-capture.py after journal rows land).

    Date → day file map¶

    Visit Jul 2–22, 2026 (21 visit days). Journal sync uses calendar date (Warsaw) to pick the file:

    Visit day Calendar Curriculum file
    1 2026-07-02 (Thu) week-01-foundation/day-01
    2 2026-07-03 (Fri) week-01-foundation/day-02
    … … …
    7 2026-07-08 (Wed) week-01-foundation/day-07
    8 2026-07-09 (Thu) week-02-mind/day-01
    … … …
    21 2026-07-22 (Wed) week-03-social/day-07

    Full table: curriculum/README.md § Visit calendar.

    Outside Jul 2–22 → no-op (remote Week 4 uses Telegram Prove + STATUS, not day files).

    Wrap-up (agent)¶

    When Sergei reports B-Unit execution in chat or wrap-up (not only Telegram):

    1. Map today's Warsaw calendar date → visit day → day file (table above).
    2. Append bullets under that file's ## Done (visit meta line is stamped automatically).
    3. Update STATUS.md + today's brief ## Log if state shifted.
    4. Never edit Sergei's vault journal prose — only the B-Unit day file ## Done block.

    Run sync manually if needed:

    python3 System/capture/b_unit_day_log_sync.py              # today
python3 System/capture/b_unit_day_log_sync.py 2026-07-02   # one date
python3 System/capture/b_unit_day_log_sync.py --all-visit  # rescan Jul 2–22 vault dailies

    Rules¶

    • Append-only on ## Done — never rewrite the Learn/Do/Prove plan sections.
    • Idempotent — same HH:MM + text is not duplicated.
    • Bim first — don't log embarrassing details Bim would veto for TikTok; ops notes OK internally.
    • Credentials — if a journal line looks like a secret, journal-capture skips it; b-unit sync never runs on skipped rows.
