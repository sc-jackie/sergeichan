    daily-linking¶

    Purpose: daily pass that weaves the day's new/changed notes — including journals — into the vault's link graph. Auto-link only high-confidence connections; report the rest for Sergei to confirm. Trigger: last step of morning-brief after brief delivery + coo-cache (preferred), or on demand "daily linking". Standalone Cowork jackie-os-daily-linking is retired — disable that scheduled task. When folded into morning-brief: write only — the brief run's single end-of-run commit includes links.md. Role: COO. Output: Vault/Briefs/YYYY-MM-DD links.md (its own file — never the brief note). Model: Haiku 4.5 — the "illuminate-together" test is structural (do two notes co-explain a third concept?), not deep reasoning. Inputs are capped at ~30 notes, most outputs are 5 auto-links + a Review list. Sonnet/Opus is over-spec; promote individual hard calls to Sonnet manually if a run flags an ambiguous edge.

    What this skill is for (and what it isn't)¶

    There are two link systems in the vault. Backlinks (Obsidian's panel) are automatic and complete — every [[wikilink]] that already exists shows up for free, no maintenance. This skill does not chase volume; backlinks already cover that. Its job is the few strong edges Obsidian can't surface on its own — pairs of notes that illuminate each other but were never explicitly linked. "Smart" means selective, not prolific. Never auto-link on shared topic alone — reading the two together must reveal something neither does alone ([[Style guide]] standard). Respect first-mention-only; don't link-spam.

    How journals participate¶

    Journals (dated YYYY-MM-DD.md at vault root + yearly Journals/Archive/Journal 20XX.md) are archive material — hard rule: never edit their inner content (Vault/CLAUDE.md). They join the graph in two ways, weighted toward the first:

    1. INBOUND (primary, always safe). When a journal connects to a stable note (evergreen, reference/person, place, thesis), add the link on the stable note, pointing into the journal — never touch the journal. This is the highest-value direction (it answers "where did this come from?") and the pattern the vault already uses (e.g. Mari.md → "runs through [[Journal 2017]], [[Journal 2018]]"). Put it in the stable note's ## See also (create one if absent).
    2. Old content → anchor to the yearly Journal 20XX note (the stable linkable unit). Current content → the specific daily YYYY-MM-DD.md.
    3. FOOTER (secondary, sparing). Only when a journal entry clearly seeded a specific evergreen, append a ## See also block at the very end of that journal — below Sergei's writing, never woven into it (same append-only precedent as journal-capture). One or two links max; if unsure, prefer inbound instead and leave it for Review.

    Process¶

    Read first: CLAUDE.md (root), Vault/CLAUDE.md, Vault/Style guide.md. Inputs: all vault notes created/modified in the last 24h (skip .obsidian/ and Claude's own Briefs/). Journals are now in scope — but only via the two mechanisms above; their inner content is still read-for-context-only.

    Bound the load (token economy): cap inputs at ~30 notes, most-recently-modified first (list any overflow under Review). Load stable / non-journal notes in full, but read journals by title + first-mention scan only, not full body — that's enough to spot the 0–5 strong edges without pulling every appended line into context.

    1. Auto-link (strong only) — connections that clearly meet the standard and are unambiguous (one obvious target, no competing candidates). Add the wikilink per the rules above (inbound on the stable note; footer on the journal only for clear evergreen seeds). Cap: 5 auto-links per run — if more qualify, link the 5 strongest and list the rest under Review.
    2. Review (everything else) — plausible-but-not-certain connections, or any with competing targets: list the wikilinks + one line on what reading them together reveals. Sergei confirms; do not link these.
    3. Write the log — Vault/Briefs/YYYY-MM-DD links.md: what was auto-linked (with the one-line rationale each, marked INBOUND or FOOTER) and the Review candidates. Empty day → one line saying so; create no links.

    Rules¶

    Never auto-link on shared topic alone — illuminate, don't just relate. Wikilinks only. Never edit journal inner content; the only journal write allowed is an append-only ## See also footer at the end, and only for a clear evergreen seed. Never rename notes. For inbound links, keep the added line structural and sourced (where the connection lives + a short anchor), not a new interpretation — distilling the meaning is Sergei's job, not the linker's (don't delegate understanding). Don't touch a note dirty in git status from another writer (multi-writer discipline) — list it under Review instead. Standalone run: git commit — Daily linking YYYY-MM-DD. Folded into morning-brief: no commit here.
