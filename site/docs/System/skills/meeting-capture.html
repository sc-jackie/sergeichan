    meeting-capture¶

    Purpose: drain Persik meet Name: queue → append verbatim notes to the daily journal and add a dated cross-link on Vault/References/{Name}.md. Full prose stays in the daily note — person notes are an index only. Trigger: folded into journal-capture step 9 (same hourly Cowork tick) · on demand "flush meeting" · "meeting capture". Role: COO. Output: appended blocks in Vault/YYYY-MM-DD.md; ## Meetings line on person note; journal_inbox rows kind=meeting marked applied. Model: Haiku 4.5 — mechanical only (fetch queue → append daily → one index line → PATCH). No summarization.

    Process¶

    1. Load .secrets/newfin-cron.env: CRON_SECRET, NEWFIN_API_BASE.
    2. GET $NEWFIN_API_BASE/api/cron/journal-inbox?status=pending&kind=meeting&limit=20 with Bearer CRON_SECRET.
    3. If empty → stop (report 0). Short-circuit before git work (same as journal-capture).
    4. Lock-contention defer — same rules as journal-capture § 3b: if Jackie-OS git lock persists after wait → abort cleanly; entries stay pending.
    5. git pull Jackie-OS — only when queue is non-empty.
    6. For each entry (meeting_person, text, journal_date, captured_at):

    7. Daily append — same format as journal-capture on Vault/{journal_date}.md:

      ---

**HH:MM** (Telegram · [[{Person}]])

{verbatim text}

      Use Europe/Warsaw wall time from captured_at. Create the daily from Vault/Templates/Journal entry.md if missing. - Person index — Vault/References/{Person}.md where {Person} is title-cased meeting_person (e.g. David, Andriy Kusyy): - File missing — create from Vault/Templates/Person.md, add # {Person} heading under frontmatter. - Append only under ## Meetings (create section at file end if absent):

      - YYYY-MM-DD — [[YYYY-MM-DD]] — {first ~80 chars of text, ellipsis if truncated}
      • Skip the line if an identical YYYY-MM-DD — [[YYYY-MM-DD]] entry already exists for that person.
      • Never edit biography or prior meeting lines — index append only.
      • Person enrich (6b) — if step 6 created a new References/{Person}.md (file did not exist before this entry), run person-enrich for that name in the same session before commit. Skip if file already existed (Sergei may have hand-written ## My relationship).
      • One git commit per run if any files changed: Meeting capture YYYY-MM-DD (+N entries).
      • PATCH $NEWFIN_API_BASE/api/cron/journal-inbox/{id} {"status":"applied"} for each row.
      • Report: N entries, dates touched, people indexed.

    Persik capture (Newfin side)¶

    Owner DM prefix: meet {Name}: {notes} (also meet {Name} — …). Routes to journal_inbox kind=meeting with meeting_person. Not finance intent, not a clip.

    Rules¶

    • Daily is canonical — never duplicate full meeting body on the person note.
    • Append-only on dailies and person ## Meetings — same discipline as journal-capture.
    • Credentials in text → do not write; PATCH applied and flag in report.
    • Spouse/group never enqueue meetings.
    • Yield on lock — defer to next hour; never clear Jackie-OS git locks.

    Setup¶

    Requires Newfin migration journal_inbox_meeting (kind=meeting, meeting_person column) and Persik meet Name: router deployed. Runs on the same Mac Cowork host as journal-capture.

    Person notes: public web data via person-enrich; your words stay in dailies + ## My relationship.
