    morning-brief¶

    Purpose: daily COO brief — yesterday, top 3, projects/open loops, code repos, calendar, inbox, thesis check — plus folded telegram-sweep (step 0), trade-digest (step 0b), and daily-linking (after brief). Trigger: scheduled daily 07:30, or "morning brief" / "daily brief". Role: COO. Output: Vault/Briefs/YYYY-MM-DD brief.md. (Vault/Briefs/ = Claude's briefs; Obsidian daily notes = Sergei's journal — separate things.)

    Wake-race guard — run BEFORE anything else¶

    This task is scheduled 07:30 but usually fires in catch-up the moment the laptop wakes (often 08:00–09:00). At that moment Obsidian Sync may still be pulling overnight/phone edits to disk and git hasn't fetched — so the vault on disk is stale and a brief generated now silently misses real work. See CHANGELOG for the 2026-06-14 wake-race incident.

    1. Telegram sweep (folded) — follow telegram-sweep before sync/brief so overnight clips land in the vault and the thesis check sees them. Short-circuit if the clip queue is empty (no git pull).

    Git — native only (Cowork). First line of the run — clear locks from any previous Cowork session. Never git pull / git commit Jackie-OS in Cowork bash. 

    osascript -e 'do shell script "/Users/jackie/Jackie-OS/System/scripts/jackie-os-git-native.sh sweep --force"'
    See project-sync § Git lock hygiene.

    0b. Trade digest (folded) — drain Persik closed-trade learnings into [[Trading playbook]] (vault narrative only — not where hard rules live; those stay in Newfin profile_facts / advisor_memory). Mechanical append; no interpretation. 1. Load .secrets/newfin-cron.env: CRON_SECRET, NEWFIN_API_BASE. 2. GET $NEWFIN_API_BASE/api/cron/journal-inbox?kind=trade_digest&status=pending&limit=20 with Bearer CRON_SECRET. 3. If empty → skip (no git work for this step). 4. osascript -e 'do shell script "/Users/jackie/Jackie-OS/System/scripts/jackie-os-git-native.sh pull"' — only if not already pulled this run. 5. For each row, append to Vault/Trading playbook.md (create from template below if missing):

      ```
  ---

  **YYYY-MM-DD** (trade close)

  {verbatim text from inbox row}
  ```

  Use `captured_at` date (Europe/Warsaw) for the heading.
    1. PATCH …/journal-inbox/{id} {"status":"applied"} for each row.
    2. If the playbook changed: stage for the single end-of-run commit (do not commit here). Report N in the session log.
    3. Settle check. Stamp the real wall-clock time (date). Stat the active project notes (Vault/{Newfin,Jackie OS,Rodyna,Draw,Peaches Beauty}.md), today's + yesterday's daily notes, and Vault/hot.md. Wait ~90 s, re-stat. If any mtime changed, the vault is still syncing → wait another ~90 s and repeat (cap ~5 min). Proceed only once two consecutive stats match (sync quiesced), or the cap is hit — in which case say so in the brief ("generated before vault sync settled — verify").
    4. Fetch. Run project-sync's git fetch (step 0) so origin refs are as fresh as the machine allows.
    5. Never hardcode the run time. The Log section uses the real fire time from step 1, not "07:30".

    Prompt caching — the stable prefix¶

    The "Read first" block (CLAUDE.md, Vault/CLAUDE.md, Vault/Home.md) is stable across runs — same bytes every day until those files are edited. When the runner supports prompt caching (Anthropic cache_control: ephemeral, Gemini cachedContent), tag that block to land in cache; on a typical morning brief it's the dominant share of input tokens. hot.md and yesterday's brief change daily and are not cache candidates. Pinning the prefix typically cuts daily-brief input cost by ~50–80%.

    Source of truth — notes over cache¶

    Project status in the brief is derived from each active project note's ## Status — read it in step 2 using the rolling work window below, not only the newest block. hot.md and yesterday's brief are orientation only; never let them author the project narrative. If a note's Status records shipped/pushed work that the local git number doesn't reflect (common: pushed from another machine, sandbox can't fetch), report the note's account and flag the git delta as unverified — do not downgrade a project to "blocked/stalled/carried" when its own note says otherwise.

    Ops kanban (Vault/Ops/Tasks/, Vault/Ops/Plans/) is the forward-looking execution layer — what Sergei (or agents on wrap-up) marked todo · doing · blocked · active on the boards. Read it in § Ops board after project-sync, before Today + Projects. When Ops and vault Status disagree on blocked/next, Ops blocked tasks win for icons and Attention; Status Next: still leads Projects prose unless every open task is blocked.

    Ops board (kanban)¶

    When: Vault/Ops/Bases/Work.base exists (skip section if missing) or any registry row is tracker: linear.

    Two task sources, by registry tracker flag (see registry § Tracker switch):

    • tracker: bases (default, every non-migrated project) — read all notes in Vault/Ops/Tasks/*.md and Vault/Ops/Plans/*.md, parse frontmatter: project, status, priority, title, blocked, kind. (Unchanged.)
    • tracker: linear (B-Unit today) — do not read that project's Ops Bases cards; its tasks come from Linear. Step 0's project-sync already ran System/scripts/linear-fetch.py --project "<name>" (§ C2) — reuse that JSON, or re-run it (cheap, read-only). Map: open/top_candidates → Todo/Doing candidates (Linear statusType started = doing, unstarted = todo, backlog = backlog); recently_done → Since last brief · Work; a top_candidates item whose body marks it blocked → Blocked. Linear priority 1/2 ≈ P1/P2 for Top-3 ranking (priorityName in the JSON). If the fetch returned an error field (missing key / API hiccup), note "Linear unread — {reason}" in Log and fall back to that project's vault ## Status Next: only.

    Aggregate:

    Bucket Rule
    Doing status: doing — global count; list by project (priority asc)
    Blocked status: blocked — list title + project; include blocked: field when set
    Todo P1 status: todo and priority: 1 — Top 3 candidates
    Active plans status: active in Plans/ — one line per project if any
    WIP flag >3 doing globally → ⚠️ in Log + mention in Today or Attention

    Feed into brief sections:

    1. Today · Top 3 — prefer, in order: 🔴 inbox · doing tasks (finish before starting new) · todo P1/P2 · calendar-hard commitments · vault Status Next:. Max one slot per project when possible.
    2. Projects icons — start from vault lane / Status Blocked:, then adjust:
    3. 🔴 if any blocked task on board for that project or Status blocked
    4. 🟡 if doing tasks exist but nothing blocked
    5. 🟢 default when on track
    6. Append · {N} blocked when N>0 (short — titles live in Attention)
    7. Attention — Ops · blocked subsection when any blocked tasks: up to 5 bullets **{Project}** — {title} (+ reason from blocked: field). Heads-up if lane: active but tasks blocked (Peaches pattern).
    8. Projects line — still Next from Status; may add · doing: {title} when exactly one doing task (optional, keep one line).

    Do not duplicate full kanban in the brief — counts + blocked titles + doing list only. Done tasks/plans live in Since last brief · Work via Status/git, not Progress table.

    Rolling work window (heavy sprint days)¶

    Calendar midnight alone loses work that spans evenings and overnight sessions (common on Rodyna/Newfin sprints). Use a rolling window ending at brief generation time:

    1. Window start — the earlier of: (a) timestamp in yesterday's brief ## Log first line (real fire time), or (b) 24 hours before brief generation (Europe/Warsaw). Never use calendar "yesterday 00:00" alone.
    2. Status prepends — for each active project, read every *YYYY-MM-DD …* block under ## Status whose stamp falls in the window. Do not stop at the newest block.
    3. merge-poll blocks — include every (merge-poll) entry in the window (they may list 25 commits with a total count when truncated).
    4. Git delta — for each registry git row: git log <window-start-ish>..origin/<branch> --oneline (also compare to lastSyncedSha from project-sync-state.json; use whichever baseline catches more commits). If ≥15 commits or ≥3 distinct themes for a repo, Yesterday · Work and Projects MUST use themed bullets (3–5 max per project), not one PR-centric paragraph.
    5. Theme buckets (suggested labels): UI/miniapp, ingest/bot, catalog/data, perf/infra, docs/plans. Latest ## Status Next/Blocked still sets what's open today.

    Process¶

    Read first: Vault/hot.md (session cache — fastest orientation), then CLAUDE.md (root), Vault/CLAUDE.md, yesterday's brief. Do not read Home.md for ops — drill into project notes ## Status per ops-board § Agent orientation.

    1. Project sync (sole owner) — follow project-sync so all projects (code repos, Projects/*/STATUS.md, vault notes) reflect overnight work in any tool — write/stage only; do not commit yet. This is the only morning task that syncs the vault. No freshness gate: always run. If git fetch can't reach GitHub (sandbox), honor project-sync's stale-origin rule — never regress a project whose note records newer pushed work. 0c. Ops board scan — when Vault/Ops/Bases/Work.base exists, run § Ops board aggregation (Tasks + Plans frontmatter). Hold results for steps 2–4.
    2. Since last brief — two parts: work, then life.
    3. Work — follow Rolling work window: all Status prepends + merge-poll entries + git log in the window. Per active project, lead with what shipped as a short narrative; on sprint days use themed bullets (3–5 max), not one latest-PR paragraph. Route Shipped: lines from Status prepends here. Carry forward unfinished items. Respond explicitly to anything Sergei wrote in {curly brackets}.
    4. Life — read yesterday's daily note Vault/{yesterday YYYY-MM-DD}.md (and skim the last 2–3 days + today's note for continuity). Synthesize, don't just recap (Sergei has opted into depth here): the emotional/experiential arc, what genuinely seemed to matter, threads that recur across recent days, and tensions or shifts worth noticing. Close with one gentle observation or open question offered for his reflection — tentative, in service of his own thinking, never a clinical verdict. Always link → [[yesterday's date]]. Hard rules: skip anything tagged #private (or in a private note) entirely — don't read, quote, or synthesize it; never edit the journal; the deep cross-week patterns stay in the weekly review (this is the daily, lighter touch). If yesterday's note is empty/missing, say so in one line and link today's [[date]].
    5. Today — propose Top 3 using Ops board candidates + open loops and calendar; include Calendar events (or "none"); fold Review reminders here when week/month artifact missing (step 11 rules). Sergei overrides. If doing >3 globally, add one line: "WIP high — {N} in flight."

    Calendar (required before glance + Today): fetch all timed events today in Europe/Warsaw — including evening — from Google Calendar (Cowork connector) or macOS Calendar.app (Google-synced calendars). Count every timed event; do not write no events without a live fetch. Family/shared calendars matter (e.g. Сім'я). Resending Telegram (brief-to-telegram.py) does not refresh calendar — patch the vault brief first if events were missed at generation.

    Weather / location (glance line): run ~/.hermes/scripts/google-life-fetch.py (or read its output in the VPS prompt). It infers current city from recent journals + briefs + hot.md (e.g. Italy trip → Bologna weather, not Warsaw). Override with BRIEF_WEATHER_CITY=bologna in .secrets/google-oauth.env if inference is wrong. The 🌤️ line must use the inferred city — never default to Warsaw when vault says Sergei is traveling. 3. Projects — apply the rolling work window for context but write forward-looking only: icon from Ops board rules + Next/Blocked from Status + inline (main sha) per active project. On sprint days add Shipped → see Since last brief · Work — do not repeat ship narrative. Append git ⚠ under a project when dirty / behind / origin-unverified (replaces the old code-repos table). Dormant rows only if blockers in vault Status. [[Jackie OS]] line = system/engineering only (skills, workflows, infra) — not vault content. 4. Attention — Ops · blocked first when step 0c found blocked tasks (≤5 bullets); then Inbox action items (🔴/🟡 only + one heads-up line); then Read queue (count + 3 oldest unread → [[Read Later]]). Regenerate Vault/Read Later.md from the clippings scan (same rules as old step 7). Omit subsections when empty. 5. Signal — Knowledge (24h vault additions: count + 2–3 highlights) + Thesis check (contradictions only; omit subsection when none). Skip #private. Skill improvements (removable nudge): count open rows in skill-feedback; if ≥1, add one line — 🛠️ N skill improvement(s) pending — say "improve skills" to review diffs; omit the line entirely when zero. 6. Log (vault only) — fire time, sync, Telegram delivery results. Not included in the DM body.

    Review rules (for Today section): nudge period closes only when Sergei's period note is still missing:

    - **Week close** — if today is **Saturday, Sunday, or Tuesday** and vault root `YYYY-Www.md` for the **current ISO week** does **not** exist: remind — read `[[YYYY-Www brief]]` (Sun auto) · run **`weekly review`** to write your week.
- **Month close** — if today is in the **last 3 calendar days of the month** OR **days 1–3 of a new month**, and prior month's `YYYY-Mmm.md` (e.g. `2026-M06.md`) is missing: if brief exists, remind read + **`monthly review`**; else **`monthly review`** to generate brief first.
- **Year close** — if today is **Jan 1–7** and prior year's `YYYY.md` is missing: if `Briefs/YYYY brief.md` exists, remind read + **`yearly review`**; else generate brief first. Optional soft line Dec 26–31: "year close soon."
- If none apply → omit review lines in Today (don't nag).

    💰 Trading learnings (vault archive). Step 0b drains trade_digest closes into [[Trading playbook]] — optional mention under Signal when step 0b applied rows overnight.

    Output format¶

    Write the brief to the template below. It is built to be scanned in 15 seconds, then read in 2 minutes — a TL;DR + at-a-glance line up top, then short sections. Telegram DM is the phone reader (brief-to-telegram.py): plain prose beats meta (no "rolling window", "Shipped:", or cross-refs like "see Since last brief").

    Voice rules:

    • TL;DR — max ~25 words. Outcome + today's lever. No commit counts or PR numbers.
    • At a glance — one plain line with · separators. No backticks. Weather · calendar · inbox count · top lever.
    • Today — numbered list; each item = bold verb phrase + one short why.
    • Since last brief · Work — lead with what changed for the user, not git stats. Sprint days: 4 bullets max per project, plain labels (App, Ingest, etc.). Separate projects as their own short blocks — don't merge Newfin + Jackie OS into one line.
    • Projects — one line each: icon + name + Next only. Icon from Ops blocked/doing rules. Optional · N blocked suffix. No sha, no "Shipped → see…" footnotes.
    • Attention — Ops · blocked first (kanban), then inbox. One heads-up paragraph for non-action items.
    • Signal — 2–3 lines max unless thesis moved.

    Status icon legend (use consistently):

    • 🟢 on track / shipped · 🟡 needs attention / in progress · 🔴 blocked · ⚪ dormant

    Section headings: Scan (TL;DR + bar inline) · Today · Since last brief (Work · Life) · Projects · Attention · Signal · Log (vault only).

    Rules¶

    Wikilinks only; YYYY-MM-DD; Russian/English mix fine; never edit journals; never rename notes. Emoji are structural signposts — one per section heading + the status legend; don't pepper them through prose. Keep the at-a-glance bar to one line. After writing the brief, deliver it to Telegram first (§ Telegram delivery — decoupled from git), then add today's row to the [[Daily]] index (daily note + brief links, newest first — the daily-note link may be unresolved until Sergei writes it) and the brief to [[Briefs]] under Daily. Run daily linking (§ Daily linking) before the commit. End with one native commit for the whole run (project-sync + brief + indexes + trade-digest + links.md): 

    osascript -e 'do shell script "/Users/jackie/Jackie-OS/System/scripts/jackie-os-git-native.sh commit Daily brief YYYY-MM-DD"'
    Adjust the message for clip/link counts when useful. Never git commit in Cowork bash. If commit fails (live non-empty lock from another writer), log git: deferred in Log — brief delivery already happened; do not retry or call allow_cowork_file_delete.

    Telegram delivery (Persik — one message: caption + HTML file)¶

    Decoupled from git — deliver FIRST. After writing Vault/Briefs/YYYY-MM-DD brief.md, before git commit.

    1. Send brief (single message)¶

    Mac (has telegram.env): 

    python3 System/coo/brief-to-telegram.py "Vault/Briefs/$(date +%F) brief.md"

    VPS (no bot token — uses Newfin API): 

    python3 ~/.hermes/scripts/brief-deliver-via-cron.py "Vault/Briefs/$(date +%F) brief.md"
    Requires POST /api/cron/coo-brief-deliver on Newfin (sendDocument + coo cache). morning-brief-vps.py calls this automatically after generation.

    • Load .secrets/telegram.env (Mac only): TELEGRAM_BOT_TOKEN, TELEGRAM_USER_ID. Missing → log skip, continue to commit.
    • One sendDocument: HTML file + caption = 🗓️ date · ⚡ outcome only (TL;DR before Today:) · one caption row per glance segment (weather, calendar, inbox — no 🎯 lever) · 🎯 Top 3 short labels. No repeated levers across lines.
    • Tap the file to read the full styled brief. Log excluded. stdout JSON: { "ok", "message_id", "caption", "filename", "html_bytes" }.

    2. COO cache (silent — no second DM)¶

    Load .secrets/newfin-cron.env: CRON_SECRET, NEWFIN_API_BASE.

    Build digest_html from Scan + Today + Projects sections (~3500 char cap, minimal HTML: <b>, <br>).

    curl -s --max-time 30 -X POST "${NEWFIN_API_BASE}/api/cron/coo-push" \
  -H "Authorization: Bearer ${CRON_SECRET}" \
  -H "Content-Type: application/json" \
  -d "{\"kind\":\"daily\",\"period_key\":\"$(date +%F)\",\"digest_html\":\"...\",\"notify\":false}"

    Missing env / 404 → log once, continue. Powers Persik /day and Ask — not a user notification.

    3. Log + commit¶

    Append to brief Log: Telegram summary + HTML attach {ok|failed}; coo-cache {ok|skipped}. Then run daily linking (§ Daily linking), then one end-of-run commit per Rules (not here).

    Weekly review still uses coo-push with default notify: true (loud digest). Daily uses notify: false after Telegram delivery.

    Daily linking (folded)¶

    After Telegram delivery and coo-cache (brief body and Log are already written):

    1. Follow daily-linking exactly — auto-link cap 5, write Vault/Briefs/YYYY-MM-DD links.md. Do not commit — morning-brief owns the single end-of-run commit.
    2. Log one line in the brief Log: daily-linking: N auto-linked, M for review (or empty day).
    3. One native commit via jackie-os-git-native.sh commit (see Rules). Post-commit sweep is inside the script.

    Run linking after the brief file exists; linking does not edit the brief body. Haiku is fine for linking (per daily-linking skill). Retired Cowork tasks: see CHANGELOG.

    Knowledge candidates (folded)¶

    During Attention, surface up to 3 clips ready for Knowledge action:

    • knowledge_state: candidate
    • read/rated 4-5 clips missing knowledge_state
    • repeated sources that point to the same Knowledge subtopic

    Do not integrate candidates automatically. Use one-click choices like append to Knowledge, ignore, or ask me later. If Sergei approves append, follow knowledge-integration.

    During Signal, include 1-2 Knowledge highlights or open questions from relevant Vault/Knowledge/*.md when they help today's projects or decisions.
