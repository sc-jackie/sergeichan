    multi-agent-run¶

    Trigger: Sergei says "run wave N" / "multi-agent run" / "use the workflow for this", or a plan doc exists with ≥5 independent, well-specified tasks. Requires explicit owner opt-in — never launch a Workflow for inferred scale.

    Proven shape (2026-07-08 Wave 1: 11 tasks, 22 agents, 13 min, 9/11 first-pass): spec → dry-run verify → Workflow(worker→verifier per task) → lead merges → gates → wrap-up.

    Phase 0 — Spec (before any agents)¶

    1. Every task gets: unique ID, repo, exact file paths, concrete steps, acceptance criteria a verifier can check against a diff, effort, dependencies. One task = one worker with zero follow-up questions.
    2. Separate owner-manual tasks (secrets, prod migrations, product decisions) into an OM-* list — never delegate those.
    3. Dry-run verify the spec itself: one read-only agent per repo checks every path exists and every claim is true. (Wave 1: this caught 5 spec errors — wrong dirs, a client-side env var listed as server-required, already-existing glossary terms.)

    Phase 1 — The Workflow script¶

    Shape (see System/plans/2026-07-08-worker-handoff-plan.md § Appendix for a full example):

    pipeline(IDS,
  id => agent(workPrompt(id), { label: `work:${id}`, phase: 'Work', model: 'sonnet' }),
  (report, id) => agent(verifyPrompt(id, report), { label: `verify:${id}`, phase: 'Verify',
    model: 'sonnet', schema: { type:'object', properties:{ pass:{type:'boolean'}, reasons:{type:'array', items:{type:'string'}} }, required:['pass'] } })
    .then(v => ({ id, ...v })))

    Hard-won rules:

    • Worktree isolation per worker, via explicit git command in the prompt — git -C <repo> worktree add <ABSOLUTE scratchpad path>/wt-<id> -b agents/<id> <base>. Workers commit on their branch, never push. Use absolute literal paths in prompts — template variables get mangled by workers (Wave 1: ${scratchDir} came through as undefined/ for 10 of 11 workers; work survived only because branches share the repo's object store). The Workflow tool's built-in isolation:'worktree' only covers the session repo — explicit git worktrees work across repos.
    • Verifier gets a schema (pass: boolean + reasons), never string-match verdicts (Wave 1 bug: 4 verifiers wrote prose before "PASS" and were miscounted as FAIL). Verifier checks the branch diff, treats the worker's report as untrusted, and also confirms nothing out-of-scope changed.
    • Standard RULES block in every worker prompt: read repo CLAUDE.md; never touch draw / Vault journals / private notes / .obsidian / .secrets; wikilinks in vault docs; git status first — dirty-from-another-writer → STOP and report.

    Phase 2 — Lead closes (never delegate this)¶

    1. Read verdicts yourself — verifiers err strict (line-number nits) and loose (phantom "file missing" claims); spot-check disputed facts before rerunning anything.
    2. Merge PASS branches sequentially (git merge --no-ff); overlapping-file conflicts are expected and small — keep both edits. Fix trivial verifier nits at merge time instead of re-running the worker.
    3. Re-run true failures as single Agent calls with the corrected instruction (cheaper than workflow resume for 1-2 tasks).
    4. Gates before push: repo checks (newfin: typecheck + tests; jackie-os: link-check). Then push.
    5. Cleanup: git worktree remove each + git worktree prune + delete agents/* branches. Check for stray undefined/ dirs inside repos.
    6. Wrap-up per wrap-up: roadmap reconcile (plan row → wave status), vault Status prepend, brief Log, push.

    When NOT to use¶

    <5 tasks, tasks with sequential dependencies on each other's output, exploratory/unspecified work (spec it first), or anything touching prod state (that's an OM item).
