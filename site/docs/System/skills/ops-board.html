    ops-board¶

    Purpose: Trello-style tracking — one card = one note. Per-project kanbans and roll-up boards read the same Vault/Ops/Tasks/ + Vault/Ops/Plans/ folders (filtered views, always in sync). Trigger: wrap-up, project-sync; on demand — "ops board" / "sync tasks". Hub: [[Ops/Dashboard — Ops|Dashboard — Ops]] · Per-project: [[Ops/Project Ops/Index|Project Ops Index]].

    Agent orientation¶

    Authoritative state = each project note ## Status + live frontmatter on notes in Vault/Ops/Tasks/ and Vault/Ops/Plans/. Kanban columns are derived from that frontmatter — not the other way around.

    Never parse .base files — they are Obsidian Bases views (filters over the same markdown cards). Agents read and write the .md card notes only.

    Read order: hot.md is the fast session index (~500 words). Drill into the relevant project note ## Status when you need depth — not [[Home]]. Ops kanban cards supplement execution tracking; they do not replace Status.

    Minimal bootstrap: repo CLAUDE.md → Vault/hot.md → Vault/CLAUDE.md → target project note ## Status (and Vault/Ops/Tasks/ only when doing ops work).

    Sync model (critical)¶

    Layer Board file What it shows
    Roll-up tasks Vault/Ops/Bases/Work.base Open tasks in Tasks/ (+ Archive for shipped history)
    Roll-up plans Vault/Ops/Bases/Plans.base Open plans in Plans/ (+ Archive for shipped history)
    Per-project Vault/Ops/Bases/ByProject/{key}.base Same cards, filter project == "[[…]]"

    Drag a card on Newfin Ops → Tasks and it moves on Work · Trello instantly — same file, same status frontmatter. No duplicate boards.

    Per-project hubs¶

    Each project has its own .base file — Vault/Ops/Bases/ByProject/{key}.base — open in Obsidian as a native Bases tab (not markdown embed). Views:

    View Type
    Trello Tasks kanban (primary — same as Tasks view)
    Plans Plans kanban
    Progress Done table

    Linked from project vault notes (## Ops) and [[Ops/Project Ops/Index|Project Ops Index]]. Workspace Jackie Ops has a tab per project (Newfin · Tasks, Newfin · Plans, …).

    Vault/Ops/Project Ops/{Name} Ops.md also embeds boards for reading in preview:

    Board Folder Columns
    Tasks Tasks/ backlog → todo → doing → blocked (shipped → Archive/Tasks/)
    Plans Plans/ backlog → planned → active → deferred (shipped → Archive/Plans/)
    Progress table shipped cards in Archive/Tasks/ + Archive/Plans/ (sort by done date)

    Task schema (Vault/Ops/Tasks/)¶

    title: Card title
kind: code | non-code
project: "[[Newfin]]"
status: todo          # backlog | todo | doing | done | blocked
priority: 1
source: manual | hot | brief | status | merge | future-improvements
created: YYYY-MM-DD
done:                 # set when status → done
blocked:

    Plan schema (Vault/Ops/Plans/)¶

    title: Plan title
kind: code | non-code
project: "[[Newfin]]"
status: backlog       # NEW plans always backlog | planned | active | deferred | done
priority: 1
source: roadmap | future-improvements | status | strategy | merge
created: YYYY-MM-DD
done:                 # set when status → done (shipped work)
repo_plan:            # path to repo STATUS / roadmap / future-improvements line

    Tasks vs plans: tasks = this week/session; plans = tracked initiative until done.

    Plan lifecycle (agents)¶

    Event Action
    New row in future-improvements.md / roadmap / Projects/*/plans/ Create plan note → status: backlog, source: future-improvements or roadmap, set repo_plan
    Owner commits / promotes to dated plan in repo backlog → planned or active
    First task for plan moves to doing Plan → active if still backlog/planned
    Ship + catalog cleanup / roadmap reconcile Plan → done + done: <today>; remove matching backlog duplicate
    Deferred explicitly status: deferred

    Do not create a task for every catalog line — plans hold ideas; tasks hold execution.

    Project note frontmatter¶

    kind: code | non-code
lane: active | blocked | parked | dormant
next: one line
blocked:
ops_updated: YYYY-MM-DD

    Agent rules — project-sync (section F)¶

    1. Set kind, next, blocked, ops_updated, lane from registry + latest Status.
    2. Do not edit Vault/Ops/Tasks/ or Vault/Ops/Plans/ in project-sync.

    Agent rules — wrap-up¶

    Tasks

    1. Shipped work → matching doing task → done + done: date → move the card to Vault/Ops/Archive/Tasks/ (rename {project}-done-{slug}.md if not already).
    2. Stale doing → todo if pivoted.
    3. Status Next: / Projects/*/STATUS.md → new todo task if no open match.
    4. Blockers → blocked task or update existing.
    5. WIP ≤3 doing globally.

    Plans

    1. On ship (roadmap reconcile): matching plan → done + done: → move to Vault/Ops/Archive/Plans/.
    2. On catalog pull: new Vault/Ops/Plans/ note per net-new future-improvements line → backlog.
    3. Promote backlog → active when execution starts.

    Archive — shipped cards live in Vault/Ops/Archive/Tasks/ and Vault/Ops/Archive/Plans/; live folders hold only open work. Move on wrap-up, never delete.

    Progress — derived view over Archive folders; never a third live folder.

    Morning brief¶

    When Vault/Ops/Bases/Work.base exists, morning-brief reads Vault/Ops/Tasks/ + Vault/Ops/Plans/ after project-sync — same cards as Obsidian kanban. Full contract: morning-brief § Ops board.

    Quick flags: blocked task but lane: active · global doing >3 · active plan with zero open tasks.
