    VPS Service Operations¶

    Use this skill when changing or diagnosing services on Sergei's VPS (hermes-phase1): Hermes gateway/dashboard, newfin-server, autodeploy scripts, cron/service self-healing, systemd user units, health checks, and related runbooks.

    Core workflow¶

    1. Assume this agent is already on the VPS unless proven otherwise.
    2. For Sergei's Newfin/Jackie-OS work, this Hermes Agent usually runs directly on hermes-phase1 with local access to /home/hermes/code/newfin, /home/hermes/jackie-os, .env.vps, systemd, and the VPS Hermes auth/session state.

    3. Do not ask the user to SSH into the VPS for actions this agent can perform locally.

    4. Diagnose before changing.

    5. Identify the real unit name first: 
      hermes gateway status || true
systemctl --user list-units --all --no-pager | grep -Ei 'hermes|gateway'
systemctl --user list-unit-files --no-pager | grep -Ei 'hermes|gateway'
    6. For root cause, inspect both current state and the incident window: 
      journalctl --user -u <unit> -n 150 --no-pager
systemctl --user show <unit> -p ActiveState -p SubState -p Restart -p NRestarts -p Result -p ActiveEnterTimestamp

    7. Report a one-line root cause that distinguishes: one-off crash/network/provider issue vs recurring startup/config issue vs missing watchdog/ops gap.

    8. Guard service-health checks inside automation.

    9. Autodeploy/cron scripts must be fail-open around health checks: never let a bad systemctl --user/hermes state break unrelated deploy flow.
    10. Use bounded calls: 
      timeout 25s hermes gateway status >>"$LOG" 2>&1
timeout 45s hermes gateway restart >>"$LOG" 2>&1
    11. Restart at most once per tick, log healthy/no-op vs restart attempts, and always return success from watchdog helper blocks.

    12. Do not re-enable retired services (e.g. hermes-ops-server) unless the user explicitly asks.

    13. Verify without killing your own control plane.

    14. If the active agent session is running inside the service being tested (e.g. hermes-gateway.service), do not stop/kill that unit from inside the same session and claim a live revival test. It can kill the agent/tool cgroup before results are reported.

    15. Instead, run non-destructive verification now (bash -n, healthy no-op tick), and for destructive paths either use a fake binary/temp harness to exercise restart branches or document/run a supervised maintenance-window test from outside that service.

    16. Use temporary ad-hoc verification scripts when no canonical suite exists.

    17. If the changed file is a shell/ops script with no project test suite, create /tmp/hermes-verify-*.sh via an OS-safe temp path.
    18. Verify syntax, guard presence, healthy path, and failure/restart path with fakes where possible.

    19. Clean up the temp script and summarize explicitly as ad-hoc verification, not suite green.

    20. Document compound-worthy incidents.

    21. For non-trivial outages or watchdog fixes, add a concise docs/solutions/... incident/runbook entry with: symptoms, root cause, fix, verification, and prevention.
    22. Update Vault/hot.md at session end with current service state and any caveats.

    Pitfalls¶

    • hermes gateway status can be healthy while provider/auth warnings exist in logs; do not conflate model/provider failures with the gateway service being down.
    • A systemd unit may have Restart=always but still need an external watchdog for dark/down states, disabled unit-file state, or health states the process does not expose as a crash.
    • Autodeploy scripts may self-update/reset the checkout before commit; after test runs, re-check git status and confirm your intended edits are still present before committing.
    • If sparse checkout hides newly merged docs, expand sparse patterns deliberately (e.g. include docs/solutions/) before editing and committing runbooks.
